# Accessibility and performance evidence, 2026-10-05 (IN-12 F-12.4)

The launch journeys ran in a real browser with axe; the Phase 1 load bursts ran against a booted API. Machine: one laptop running the local Homebrew stack and Chrome through Playwright 1.63 (`E2E_CHANNEL=chrome`). The nightly repeats both on CI with Playwright's Chromium.

## Launch journeys (doc 21 §9)

`pnpm --filter @jobwork/e2e e2e`. Each run prepares `jobwork_e2e` from scratch (`e2e/scripts/prepare-db.mjs`). A setup project then builds the records the journeys act on, over HTTP: an enquiry at intake, a quotation waiting for the customer, an order with a purchase order waiting for the supplier, and an award waiting for approval. Axe runs the WCAG 2.1 A and AA rules; a serious or critical violation fails the screen.

| Journey | Screens checked with axe | Keyboard-only path |
|---|---|---|
| Customer sign-in | Home | Email, password, Enter |
| Enquiry wizard | Details, requirements, review; submitted with a reference | — (pointer; fields by label) |
| Quotation decision and acceptance | Quotations list, quotation, acceptance | Consent with Space, Tab to Accept, Enter |
| Order tracking | Order | — |
| Supplier RFQ | RFQ list, RFQ detail | — |
| Supplier purchase order | Purchase order | Note, Tab, Enter to acknowledge |
| Operations intake | Intake queue, intake detail | Sign-in with TOTP |
| Operations queues | Work queues, RFQ control room | — |
| Operations approvals | Approvals, decision panel | Enter on "Decide…", Enter on "Approve" |

**Result: 10 of 10 pass**, after the fixes below. The journeys also check that the customer's screens never name a supplier and the supplier's never name the customer.

### Defects found and fixed

| Defect | Where | Measured | Fix |
|---|---|---|---|
| Table header text below the 4.5:1 contrast bar | Every `DataTable` (queues, approvals, RFQ lists…) | `neutral-600` on `neutral-100`: 4.39:1 | New token `--color-text-muted-on-tint` (`neutral-700`, 6.72:1) |
| Currency prefix in money inputs, same pair | `MoneyInput` | 4.39:1 | Same token |
| Description inside a selected choice card | Enquiry wizard, every choice-card group | `neutral-600` on `blue-50`: 4.41:1 | Same token for the selected state (6.75:1) |
| Navigation badge still counting an item the person had just decided | Both shells | "Approvals 1" next to "Nothing waiting" | `CommandButton` announces success, and the shells refetch their counts on it (`useCommandTick`) |

The component axe suite could not catch the contrast defects, because jsdom computes no colours. The token contrast test (`packages/ui/test/tokens.spec.ts`) now pins every muted-on-tint pair, so a future palette change fails there first.

## Load bursts (`NFR-02`: p95 under 500 ms)

`pnpm --filter @jobwork/api perf` (`apps/api/test/perf/phase1-load.perf.ts`). Two runs on 2026-10-05:

| Burst | Concurrent | Must stay true | p50 / p95 / p99 (ms), run 1 | Run 2 |
|---|---|---|---|---|
| RFQ deadline: every invited supplier submits at once | 24 | 24 bids, each exactly one live version | 34 / 38 / 38 | 55 / 61 / 62 |
| Sibling-option acceptance race | 30 across 3 options | Exactly one 201, all others 409; one acceptance; the other two options withdrawn | 41 / 53 / 54 | 48 / 62 / 63 |
| Upload finalize | 20 | 20 distinct document versions | 44 / 48 / 48 | 22 / 26 / 26 |

**Result: pass.** Correctness held in every burst, and the p95 is about a tenth of the objective. These are laptop numbers on a small database. They show the paths are not pathological under contention; they are not a capacity claim. Capacity is measured when hosting exists (T-01, doc 12 §11).
